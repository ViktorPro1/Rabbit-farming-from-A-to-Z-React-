# Keep Supabase Alive

## Що це таке простими словами

Цей workflow — простий "пінгер", який раз на кілька днів надсилає запит
до Supabase, щоб база даних не "заснула".

Річ у тім, що безкоштовний (free tier) план Supabase призупиняє проєкт,
якщо до нього довго ніхто не звертається. Щоб цього не сталось,
workflow періодично "будить" базу штучним запитом.

## Коли він запускається

- **Щовівторка та щоп'ятниці о 08:00 UTC** — тобто кожні 3–4 дні,
  цього достатньо, щоб Supabase не встиг заснути.
- **Вручну** — через `workflow_dispatch`, кнопкою в GitHub.

## Що робить крок за кроком

Всього один крок:

1. Надсилає GET-запит через `curl` на адресу `SUPABASE_URL/rest/v1/`,
   передаючи `apikey` (це `SUPABASE_ANON_KEY`) в заголовку.
   Це і є той самий "пінг" — Supabase бачить звернення й лишається активним.

`SUPABASE_URL` та `SUPABASE_ANON_KEY` беруться із секретів репозиторію
(GitHub Secrets), тому в коді workflow самих значень не видно.

## Навіщо це потрібно

Без цього пінгу проєкт на Supabase міг би "заснути" через неактивність,
і тоді сайт чи застосунок, який до нього звертається, отримував би
помилки або сильні затримки при першому запиті після паузи.

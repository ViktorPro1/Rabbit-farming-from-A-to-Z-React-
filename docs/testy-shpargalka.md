# Автоматичні тести — шпаргалка

Проєкт: Кролівництво від А до Я
Стек тестування: Vitest + React Testing Library

---

## Що таке тест простими словами

Тест — це маленький скрипт, який запускає шматок вашого коду в ізольованих
умовах і перевіряє: "результат такий, як очікувалось?"

Приклад: тест для `WelcomePopup` монтує компонент, штучно "перемотує" 3
секунди вперед і перевіряє — попап справді зникає? Якщо так — тест зелений.
Якщо ні — червоний, з поясненням, що саме не збіглось.

---

## Навіщо це, якщо все й так працює зараз

Це не для сьогодні, а для майбутнього. Сценарій:

Через два місяці ви міняєте логіку `usePublicPresence` — наприклад, додаєте
нову умову. Код виглядає нормально, білд проходить. Але ви випадково
зламали стару поведінку — наприклад, `sessionId` більше не зберігається в
`sessionStorage` при повторному візиті.

- **Без тестів:** дізнаєтесь про це тільки якщо помітите баг візуально, або
  взагалі не дізнаєтесь, поки хтось не поскаржиться.
- **З тестами:** запускаєте `npm run test`, і відповідний тест одразу стає
  червоним — ще до коміту, ще до продакшену.

---

## Як це працює на практиці

Тести лежать поряд з кодом (`usePublicPresence.test.ts` поряд з
`usePublicPresence.ts`) і запускаються командою:

```bash
npm run test
```

Типові моменти, коли їх запускати:

1. **Перед комітом** — написав фічу → запустив тести → закомітив, якщо
   зелено.
2. **Коли міняєте існуючий файл** — можна запустити тести тільки для нього:
   ```bash
   npx vitest run src/App.test.tsx
   ```
3. **Автоматично на CI/CD** (ще не налаштовано) — GitHub Actions сам
   запускає `npm run test` при кожному push чи pull request, і якщо тести
   червоні — видно одразу в GitHub, ще до мержу в `main`.

## Чи треба міняти тест, коли міняю код

Залежить від того, що саме змінилось:

| Що змінилось | Що робити з тестом |
|---|---|
| Внутрішня реалізація, поведінка ззовні та сама | Нічого не чіпати, тест і так пройде |
| Навмисна зміна поведінки (новий текст, нова умова) | Оновити очікування в тесті (`expect(...)`) під нову поведінку |
| Нова фіча / новий сценарій | Додати новий тест, старі не чіпати |

Тест червоніє в двох випадках:
- ви щось зламали ненавмисно — це і є цінність, вас попередили;
- ви навмисно змінили поведінку і забули оновити тест під нову версію —
  тоді просто підправляєте очікування.

## Корисні команди

```bash
npm run test          # запустити всі тести один раз
npm run test:watch    # запускати тести автоматично при зміні файлів
npm run test:ui       # відкрити візуальний інтерфейс Vitest
```

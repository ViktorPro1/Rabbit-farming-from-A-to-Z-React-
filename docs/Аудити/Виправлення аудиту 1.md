# Кролівництво від А до Я — підсумок роботи

Довідник по всьому, що зроблено з проєктом. Для орієнтації та як історія рішень.

**Проєкт:** React 19 / TypeScript / Vite 7 довідник з кролівництва, українською, 149 сторінок, деплой на Vercel.

---

## 1. Автоматизовані тести (аудит 5.1)

Налаштовано Vitest + React Testing Library. Тестова база розрослась до **38 тестів у 7 файлах**:
`usePublicPresence`, `supabase` (клієнт), `WelcomePopup`, `CookieConsent`, `App`, `AppRoutes`, `ErrorBoundary`.

Команди: `npm run test`, `npm run test:watch`, `npm run test:ui`, `npm run test:coverage`.

---

## 2. Обробка помилок (аудит 5.3)

Створено централізовану утиліту `src/lib/logError.ts` (`logError(context, error)`).

Застосовано послідовно по всьому проєкту: `App.tsx`, `usePublicPresence`, `RabbitRegistry`, `GrainRecipesHistory`, `Calculator`, `Paddocks` (де раніше взагалі не було обробки помилок на кількох write-операціях), і зрештою — **усі решта асинхронних операцій в проєкті**.

**Error Boundary:** `ErrorBoundary.tsx` тепер логує через `logError`, має опційний `boundaryName` (контекст для трейсу) і `fallback?: ReactNode` (перевіряється через `!== undefined`, щоб `null` теж поважався — використовується для некритичних віджетів типу `Assistant`, який при краші просто зникає замість показу картки-фолбеку).

Покриття error boundary тепер повне: `Assistant` (глобально, `fallback=null`), усі 15 маршрутів особистого кабінету (через хелпер `withCabinetBoundary` у файлі групи маршрутів), `Admin`, `Calculator`.

`Assistant.tsx` розбито на: `Assistant.tsx` (оркестрація), `AssistantToggle.tsx`, `AssistantWindow.tsx`, `getBotResponse.ts` (чиста функція розпізнавання), `quickReplies.ts`, `getTimeGreeting.ts`, `types.ts`.

## 4. Дублювання сторінок та розмір AppRoutes (аудит 5.2)

**PageLayout:** створено спільний компонент (header, "читайте також", футер з кнопкою "на головну" + Share). Мігровано `BeginnerGuide.tsx` і `BuyingRabbit.tsx` як демонстрацію підходу — решта ~147 сторінок відкладені на майбутню окрему гілку.

**AppRoutes.tsx:** розбито зі 149+ маршрутів в одному файлі на **11 файлів-груп** під `src/routes/groups/` (за темами: основи, здоров'я, розведення, лікування, особистий кабінет тощо). Головний `AppRoutes.tsx` скоротився з ~500 до ~60 рядків.

**sectionCards.ts:** той самий підхід застосовано до даних для чат-асистента й пошуку — файл розбито на `src/data/sectionCards/` з `types.ts`, `index.ts` і **20 файлами-груп**. Імпорт `../../data/sectionCards` лишився без змін завдяки резолву `index.ts`.

## 5. CI/CD

Колега додав `.github/workflows/ci.yml`. Далі допрацьовано разом: 4 джоби — **Lint / Typecheck / Tests / Build**, плюс окремий **E2E**-джоб, обмежений тільки на `pull_request` (щоб економити хвилини GitHub Actions).

Виправлені по дорозі проблеми:
- `@vitest/coverage-v8` для `--coverage` — колега вже врахував заздалегідь.
- `react-refresh/only-export-components` (195 помилок) у файлах груп маршрутів — вирішено додаванням `/* eslint-disable react-refresh/only-export-components */` на початку кожного з 11 файлів.

Додано скрипти `test:coverage`, `lint:fix`.

**E2E-тести (Playwright):** 10 тестів — `e2e/routing.spec.ts` (7 тестів) + `e2e/pwa.spec.ts` (3 тести), тільки Chromium, окремий `e2e/tsconfig.json` з DOM-типами.

**PR #3** (`feature/audit-2026-08-05`) закрив усі "негайні" та "середньострокові" пункти повторного аудиту й змержений у `main`.

## 6. Оптимізація розміру бандлу

Гілка `feature/bundle-size-optimization`. Підключено `rollup-plugin-visualizer` (генерує `dist/stats.html`) для аналізу складу бандлу.

**Знайдена проблема:** чанк `AppRoutes.js` був роздутий через важкий масив `groups` (236KB / 4755 рядків з `sectionCards`) — його напряму імпортували два місця, що рендеряться на кожній сторінці поза лінивими маршрутами:

1. **`Breadcrumbs.tsx`** і **`RunningTicker.tsx`** — обом потрібні лише легкі поля (`{path: groupTitle}` і `{icon, title, path}` відповідно, без групи "Статті" для тікера). Виправлено білд-скриптом `scripts/generate-nav-map.ts` (запускається через `npx tsx`, бо звичайний `node` не резолвить безрозширенні TS-імпорти всередині `sectionCards/index.ts`), який генерує легкий `src/data/navMap.generated.ts` (в .gitignore) з `PATH_TO_SECTION` і `LIGHT_CARDS`.

2. **`Home.tsx`** — єдина сторінка, яку імпортували не через `lazy()` в файлі `coreRoutes`, і вона рендерить `<SectionCards />`, який теж тягне важкі `groups` напряму. Виправлення: `Home` тепер теж `lazy()`.

**Результат:**
- `AppRoutes.js`: 297.81KB → 111.58KB (**-62%**)
- `navMap.generated`: 173.65KB → 23.22KB (**-87%**, підтвердило, що попереднє роздуття було через `Assistant`)
- `Assistant` тепер власний лінивий чанк (11.41KB)

`SectionCards.tsx` і `Assistant/getBotResponse.ts` й далі імпортують важкі `groups` напряму — і це нормально, бо обидва тепер ліниво завантажуються (через `Home` і власний `lazy()` відповідно), тож важкі дані підвантажуються лише коли справді потрібні.

Роботу з оптимізації розміру бандлу практично завершено — залишилось прогнати повний набір тестів + e2e, закомітити і відкрити PR для `feature/bundle-size-optimization`.

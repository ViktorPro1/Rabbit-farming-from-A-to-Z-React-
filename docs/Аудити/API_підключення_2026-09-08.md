# Аудит підключень API

Дата перевірки: 08.09.2026

## Підсумок

API-підключення в коді виконані коректно: Vercel-функції використовують Supabase service role, Gmail SMTP через Nodemailer і Web Push через VAPID. Production-збірка та ESLint проходять успішно.

Автоматичні щоденні нагадування запускаються не через Vercel Cron, а через GitHub Actions. Це відповідає поточній реалізації, але розклад має неточний коментар щодо літнього часу. Реальні запити до production під час аудиту не виконувалися, тому наявність змінних середовища у Vercel, GitHub та Supabase потрібно підтвердити окремо.

## Перевірені компоненти

| Компонент           | Статус            | Висновок                                                                                                                                               |
| ------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Supabase            | Підключено        | `api/_lib/push.ts` створює серверний клієнт із `VITE_SUPABASE_URL` та `SUPABASE_SERVICE_ROLE_KEY`. Ключ service role використовується лише в API-коді. |
| Gmail SMTP          | Підключено        | `api/_lib/email.ts` використовує `GMAIL_USER` і `GMAIL_APP_PASSWORD` через Nodemailer. Помилка окремого листа не зупиняє масову розсилку.              |
| Web Push            | Підключено        | VAPID налаштований через `VAPID_SUBJECT`, `VITE_VAPID_PUBLIC_KEY` та `VAPID_PRIVATE_KEY`; недійсні підписки з кодами 404/410 видаляються.              |
| Адмінські листи     | Підключено        | Endpoint-и активації, оплати та скасування перевіряють Bearer-токен через Supabase і наявність користувача в таблиці `admins`.                         |
| Database Webhook    | Підключено в коді | `welcome-email.ts` перевіряє `x-webhook-secret` і бере email із `record.email`. У Supabase має бути створений webhook на INSERT таблиці `profiles`.    |
| Щоденні нагадування | Підключено        | `.github/workflows/daily-reminders.yml` викликає `/api/daily-reminders` щодня з `PUSH_SEND_SECRET`.                                                    |
| Ручні розсилки      | Підключено        | `send-email.ts` і `send-feature-announcement.ts` захищені `SEND_EMAIL_SECRET`; скрипти передають цей заголовок.                                        |

## Знайдені зауваження

### 1. Перевірити й за потреби відкликати production-секрети

Локальний `.env` не відстежується Git і правильно ігнорується, але містить service-role ключ Supabase, VAPID private key та секрети API. Не можна додавати цей файл у коміт, архів, скриншот або лог. Якщо значення вже десь публікувалися чи передавалися третім особам, їх потрібно негайно замінити у Supabase, Vercel і GitHub Secrets.

### 2. Виправити коментар до розкладу GitHub Actions

У workflow стоїть `06:00 UTC`. Це 08:00 за Києвом узимку, але 09:00 під час літнього часу. Якщо потрібен стабільний локальний час, GitHub Actions не підтримує часову зону в cron, тому потрібно або прийняти UTC-розклад, або змінити workflow/запускати його через сервіс із timezone support.

### 3. Перевірити змінні середовища в усіх середовищах

У Vercel Production мають бути задані:

- `VITE_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `GMAIL_USER`
- `GMAIL_APP_PASSWORD`
- `VAPID_SUBJECT`
- `VITE_VAPID_PUBLIC_KEY`
- `VAPID_PRIVATE_KEY`
- `PUSH_SEND_SECRET`
- `SEND_EMAIL_SECRET`
- `SUPABASE_WEBHOOK_SECRET`
- `SUBSCRIPTION_PRICE` за потреби для шаблону квитанції

У GitHub Actions має бути заданий `PUSH_SEND_SECRET` з тим самим значенням, що й у Vercel Production. У Supabase Database Webhook має використовуватися `SUPABASE_WEBHOOK_SECRET`.

### 4. Перевірити відповідь API в адмінці

`Admin.tsx` запускає email-запити через `fetch`, але обробляє лише мережевий `catch`. HTTP-відповідь `401`, `403` або `502` не вважається помилкою на рівні інтерфейсу. Це не ламає саме підключення, але може створювати враження, що лист надіслано, хоча API його відхилив.

## Результати локальної перевірки

- `npm run lint` — успішно.
- `npm run build` — успішно.
- `.env` — не відстежується Git, правило `.gitignore` працює.
- Реальна відправка email/push і production webhook не виконувалися, щоб не надсилати тестові повідомлення користувачам.

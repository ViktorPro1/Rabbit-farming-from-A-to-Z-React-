# Аудит проєкту «Кролівництво від А до Я» — 2026-08-06

## Обсяг і метод

Перевірено кореневий README, структуру репозиторію, налаштування Vite, TypeScript, Playwright, Vercel і CI, вихідний код `src`, E2E-тести `e2e`, наявну документацію та результати локальних команд. Це статичний аудит репозиторію: він не перевіряє налаштування Supabase, секрети, правила RLS, Vercel Dashboard або поведінку live-сайту.

## Підсумок

Проєкт — великий TypeScript SPA на React 19 із Vite, PWA, prerender, SEO, Supabase-автентифікацією та кабінетом кролівника. У репозиторії є автоматичні перевірки коду, unit- та E2E-тести, CI і конфігурація захисних HTTP-заголовків. Локальні lint і production-збірка завершилися успішно.

Основна виявлена проблема документації — кореневий `README.md` описує застарілий стек і не відповідає поточній структурі проєкту.

## Тестування

У репозиторії є 7 unit-тестів у `src` та 2 E2E-специфікації:

| Файл або група                        | Що перевіряється                                  |
| ------------------------------------- | ------------------------------------------------- |
| `src/App.test.tsx`                    | Поведінка кореневого застосунку.                  |
| `src/routes/AppRoutes.test.tsx`       | Маршрутизація та доступ залежно від сесії.        |
| `src/components/*/*.test.tsx`         | Cookie consent, Error Boundary і Welcome Popup.   |
| `src/hooks/usePublicPresence.test.ts` | Підключення Supabase Presence.                    |
| `e2e/routing.spec.ts`                 | Основні маршрути, 404 і сценарії без авторизації. |
| `e2e/pwa.spec.ts`                     | Service worker, manifest та офлайн-режим.         |

У `vite.config.ts` вимірювання покриття не включає `src/routes/groups/**`; отже, наведений відсоток не є покриттям усіх 176 маршрутів. Це конфігураційний факт, а не помилка тестового запуску.

## Безпека й приватність

Перевірені наявні механізми:

- У `vercel.json` задані `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` і Content-Security-Policy.
- CSP дозволяє з’єднання з Supabase (`https` і `wss`), Google Analytics/Tag Manager та Open-Meteo; список джерел обмежений конфігурацією.
- Підключення Google Analytics у `CookieConsent` виконується після вибору користувача для категорії analytics.
- У CI значення `VITE_SUPABASE_URL` і `VITE_SUPABASE_ANON_KEY` передаються через GitHub Secrets.
- Локальний `.env` не аналізувався й не потрапляє до цього документа, щоб не розкривати конфіденційні значення.

Що неможливо підтвердити з цього репозиторію: правила RLS та ролі Supabase, безпечність даних у віддаленій БД, фактичні Vercel-змінні середовища, стан залежностей у production та заголовки live-сайту.

## Розбіжності кореневого README

`README.md` містить корисний опис призначення застосунку, посилання на live demo, ліцензію та базові команди. Водночас він не відповідає поточному коду в таких місцях:

| У README                                                       | Фактично в проєкті                                                                          |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `JavaScript (ES6+)`                                            | Основний код — TypeScript (`.ts` і `.tsx`); увімкнено strict TypeScript.                    |
| `Vite / CRA`                                                   | Використовується Vite; Create React App у конфігурації та скриптах відсутній.               |
| `CSS / SCSS`                                                   | Використовуються CSS-файли; SCSS-конфігурації та залежності не знайдено.                    |
| `App.jsx`, `main.jsx`                                          | Реальні точки входу — `src/App.tsx` і `src/main.tsx`.                                       |
| Спрощена структура `src/components`, `pages`, `assets`, `data` | Також є `routes`, `hooks`, `lib`, `seo`, `test`, prerender-файли та великі групи маршрутів. |
| `docs/DEVELOPER_GUIDE.md`                                      | Реальний шлях: `docs/Розробка/DEVELOPER_GUIDE.md`.                                          |

## Спостереження щодо підтримуваності

- Маршрути групуються за тематикою, а сторінки збираються Vite в окремі assets; це відповідає великому обсягу контенту.
- Частина файлів велика за розміром. Зокрема: `src/pages/Matings/Matings.tsx` — 80 152 байти, `WaterMedication.tsx` — 74 694 байти, `src/seo/pageMeta.ts` — 72 966 байтів. Це не є помилкою, але такі модулі є першими кандидатами на локальне розділення під час майбутніх змін.
- `playwright-report`, `test-results`, `coverage` і `dist` — генеровані папки, виключені з Git. Для них вже є окремі пояснення у `docs/Тестування`.

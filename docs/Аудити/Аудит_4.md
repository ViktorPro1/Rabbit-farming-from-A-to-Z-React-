### Error-handling (реальний код)

**Централізоване логування є:**

```ts
// src/lib/logError.ts
export function logError(context: string, error: unknown) {
    console.error(`[${context}]`, error);
}
```

Підготовлено до підключення Sentry/LogRocket без переписування коду.

**ErrorBoundary** (`src/components/ErrorBoundary/ErrorBoundary.tsx`):
- class-component з `getDerivedStateFromError` + `componentDidCatch`
- викликає `logError(boundaryName, error)`
- підтримує `fallbackTitle`, `boundaryName`, кастомний `fallback`
- кнопка «Перезавантажити сторінку»
- є unit-тест

За заявою автора — boundaries стоять на 15 кабінетних роутах + Assistant + Admin + Calculator. Це **плюс**, який у першому аудиті був пропущений.

## 4. Чого ще не вистачає (рекомендації)

### Високий пріоритет
1. Глибший pedigree / генеалогія + візуалізація
2. Фінансовий модуль (доходи/витрати, собівартість)
3. Нагадування + календар завдань + push
4. Експорт/імпорт (CSV, PDF cage cards)
5. Покращення мобільного UX обліку

### Середній пріоритет
6. Розширення AI-асистента
7. Фото + історія ваги
8. Повноцінний offline-first для реєстру
9. Англійська мова
10. Спільнота / обмін litters

### Низький / довгостроковий
11. IoT / ваги
12. Маркетплейс
13. Аналітика продуктивності пар
14. Підключення Sentry до `logError`

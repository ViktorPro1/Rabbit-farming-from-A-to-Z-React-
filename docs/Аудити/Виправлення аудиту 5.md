## 1. Що змінили в коді

### `api/daily-reminders.ts` — обробка помилок Supabase

**Проблема:** запити до Supabase (`.select()`) деструктурувались лише як `{ data }`, без перевірки `error`. Якщо запит падав (тимчасовий збій, ліміт, мережева проблема), функція мовчки продовжувала роботу з порожнім результатом і завершувалась з кодом 200 — сповіщення могли не піти, а ніхто б про це не дізнався.

**Що зробили:**
- Кожен запит тепер перевіряє поле `error` і логує його в консоль (видно в Vercel Logs), якщо запит впав.
- У відповіді функції додано поле `failedQueries` — список запитів, які не вдалися, видно одразу в результаті виклику.
- У `sendToUser()`: якщо не вдалось отримати підписки користувача — функція виходить одразу з логом, замість тихого продовження з порожнім масивом.
- Видалення протермінованої push-підписки (при статусі 410/404) тепер теж перевіряє помилку видалення і логує її.

**Статус:** ✅ виправлено.

## 2. Що задокументували і свідомо залишили без змін

### Вразливість react-router-dom (GHSA-qwww-vcr4-c8h2, CSRF bypass)

`npm audit` показує high-severity вразливість у `react-router-dom@7.18.1`. Виправлення є лише в мажорній версії 8.3.0+.

**Чому не чіпаємо:** вразливість стосується тільки застосунків, що використовують нестабільні React Server Components (RSC) API. Цей проєкт — клієнтський Vite SPA зі стандартним client-side роутингом, RSC не використовується. Практичного ризику немає.

**Рішення:** залишити на v7, перейти на v8 окремо, коли з'явиться самостійний привід (наприклад, потреба в нових функціях v8), а не заради закриття audit-попередження.

**Статус:** ✅ задокументовано, ризик прийнятий.

### E2E тести запускаються тільки на pull request

У `.github/workflows/ci.yml` job `e2e` має умову `if: github.event_name == 'pull_request'`. Тобто якщо комітити напряму в `main` без pull request — Playwright-тести (перевірка роутингу, PWA, service worker) не запускаються, і регресія може пройти непоміченою.

**Рішення:** залишити як є — свідомий вибір заради швидшого й дешевшого CI. Прибрати обмеження можна одним рядком у будь-який момент, якщо стане критично.

**Статус:** ✅ задокументовано, залишено без змін.

# Як перетворити React/Vite PWA на Android-застосунок (TWA)

Повна інструкція на основі реального досвіду з проєкту "Кролівництво від А до Я". Підходить для будь-якого React/Vite (чи іншого) сайту з готовим PWA-манiфестом.

---

## Що таке TWA

**Trusted Web Activity** — спосіб загорнути вже готовий PWA-сайт в Android-застосунок без WebView, через Chrome Custom Tabs. При правильному налаштуванні адресний рядок браузера повністю зникає, і застосунок виглядає як нативний.

---

## Крок 0 — Передумови (має бути готово ще до початку)

Сайт має бути повноцінним PWA:
- Валідний `manifest.json` / `manifest.webmanifest` (у Vite — через `vite-plugin-pwa`)
- Зареєстрований Service Worker
- HTTPS (Vercel/Netlify дають це автоматично)
- Іконки мінімум 192×192 і 512×512, бажано ще й `maskable`-варіанти
- `display: "standalone"` у маніфесті

Перевірити маніфест на проді: відкрити `https://ваш-сайт/manifest.webmanifest` у браузері — має показати чистий JSON.

## Крок 1 — Встановити Bubblewrap

```bash
npm install -g @bubblewrap/cli
```

Перевірка:
```bash
bubblewrap --version
```

Якщо після встановлення командою `bubblewrap` система каже "команду не знайдено" — перевірити:
```bash
npm list -g @bubblewrap/cli
```
Якщо пакет є, але команда не знаходиться — проблема з `PATH`. Якщо пакета немає — встановити ще раз, подивитись на текст помилки уважно.

## Крок 2 — Створити окрему папку для Android-проєкту

**Важливо:** окремо від React/Vite-проєкту, не всередині нього.

```bash
mkdir -p ~/projects/назва-проєкту-android
cd ~/projects/назва-проєкту-android
```

## Крок 3 — Згенерувати Android-проєкт

```bash
bubblewrap init --manifest=https://ваш-сайт/manifest.webmanifest
```

Майстер запитає по черзі (у дужках — значення за замовчуванням з маніфеста, зазвичай просто Enter):

| Питання | Що відповідати |
|---|---|
| Domain | Enter (підхоплюється автоматично) |
| Application name | Ваша назва застосунку |
| Short name | Коротка назва |
| Application ID | Package name, напр. `com.example.app` |
| Starting version code | 1 (для першої збірки) |
| Display mode | `standalone` |
| Status bar color | Enter (з маніфеста) |
| Splash screen color | Enter (з маніфеста) |
| Icon URL / Maskable Icon URL | Enter (з маніфеста) |
| Include app shortcuts | Y, якщо є shortcuts у маніфесті |
| Monochrome icon URL | Enter (можна пропустити) |
| Play Billing | N, якщо не потрібні платежі всередині застосунку |
| Geolocation permission | N, якщо не потрібна геолокація |

### Створення ключа підпису

Якщо keystore ще не існує — Bubblewrap запропонує створити новий:
- **Key store location** — Enter (шлях за замовчуванням)
- **Key name (alias)** — Enter (`android` підходить)
- **Password for the Key Store** — придумати надійний пароль **заздалегідь**, ввести уважно (символи не відображаються)
- **Password for the Key** — можна той самий пароль
- Дані власника сертифіката (ім'я, організація, країна) — довільні, не критичні для функціональності

**⚠️ КРИТИЧНО:** одразу після створення:
1. Зробити резервну копію файлу `android.keystore` (хмара, флешка — окремо від основного диска)
2. Записати паролі в менеджер паролів
3. Без цього ключа неможливо оновлювати застосунок у Google Play в майбутньому — доведеться публікувати як новий застосунок

---

## Крок 4 — Зібрати APK/AAB

```bash
bubblewrap build
```

При першому запуску попросить прийняти ліцензійні угоди Android SDK — вводити `y` на кожну.

Результат:
- `app-release-signed.apk` — для тестування/прямого розповсюдження
- `app-release-bundle.aab` — для завантаження в Google Play

## Крок 5 — Digital Asset Links (assetlinks.json)

Без цього файлу адресний рядок браузера **не зникне**.

### Отримати SHA-256 відбиток ключа

Якщо `bubblewrap fingerprint generateAssetLinks` видає порожній `[]` (буває, якщо автогенерація не змогла прочитати keystore) — отримати відбиток напряму:

```bash
keytool -list -v -keystore android.keystore -alias android
```

У виводі знайти рядок:
```
SHA256: XX:XX:XX:XX:...
```

Package name перевірити тут:
```bash
cat twa-manifest.json | grep packageId
```

### Скласти файл вручну

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "ваш.package.name",
    "sha256_cert_fingerprints": ["XX:XX:XX:...відбиток..."]
  }
}]
```

### Розмістити на сайті

Покласти файл у React/Vite-проєкт за шляхом:
```
public/.well-known/assetlinks.json
```

**⚠️ Типова проблема з Vercel:** якщо у вас є `vercel.json` з `rewrites`, що перенаправляє всі шляхи на `/index.html` (типово для SPA), — `.well-known/assetlinks.json` теж потрапить під це правило і не буде роздаватись як статичний файл. Показуватиме сторінку помилки замість JSON.

**Рішення** — додати виняток у regex `rewrites.source`:
```json
"source": "/((?!sitemap\\.xml|robots\\.txt|\\.well-known/assetlinks\\.json).*)"
```

Задеплоїти (`git push`) і перевірити:
```
https://ваш-сайт/.well-known/assetlinks.json
```
Має показати чистий JSON. Якщо в анонімному режимі показує правильно, а в звичайному — стару помилку, це кеш браузера: `Ctrl+Shift+R`.

## Крок 6 — Встановити APK на телефон і перевірити

### Увімкнути режим розробника (Samsung, аналогічно на інших)

1. Налаштування → Про телефон → 7 разів тапнути "Номер збірки"
2. З'явиться "Для розробників" (зазвичай у Додаткових налаштуваннях)
3. Увімкнути "Налагодження USB" (USB debugging)
4. Підключити кабель, на екрані телефону підтвердити "Дозволити налагодження USB"

### Встановити

```bash
bubblewrap install
```

Якщо `adb: device unauthorized` — розблокувати екран телефону, перевірити діалог підтвердження на екрані.

Якщо файловий менеджер на комп'ютері не бачить телефон (MTP) — це не заважає `adb`/Bubblewrap, вони працюють через USB debugging окремо від MTP.

### Перевірити верифікацію

```bash
adb shell pm get-app-links ваш.package.name
```

Має показати:
```
Domain verification state:
  ваш-домен: verified
```

### Практична перевірка

Відкрити застосунок на телефоні. Якщо перший запуск показує коротке сповіщення "Відкрито в Chrome" — це нормальна поведінка Chrome при першому запуску, не помилка. При наступних відкриттях адресний рядок має зникнути повністю.

Якщо не зникає стабільно:
- Очистити кеш Chrome (Налаштування → Застосунки → Chrome → Пам'ять → Очистити кеш)
- Перевстановити застосунок (`adb uninstall package.name`, потім `bubblewrap install`)

## Крок 7 — Публікація або розповсюдження без Google Play

### Варіант А: Google Play Console
- Реєстрація розробника — $25 одноразово
- Завантажити `app-release-bundle.aab`
- Заповнити картку застосунку (опис, скріншоти, іконка, **обов'язкова політика конфіденційності**)
- Review триває кілька днів для першої публікації

### Варіант Б: Пряме розповсюдження (без Google Play, безкоштовно)
1. Скопіювати `app-release-signed.apk` у `public/` React-проєкту
2. Додати сторінку на сайті (наприклад `/android-app`) з кнопкою завантаження і поясненням, що потрібно дозволити "встановлення з невідомого джерела"
3. Поширювати посилання на цю сторінку (соцмережі, Telegram-спільнота тощо)

**Мінус варіанту Б:** немає автооновлень через Play Store. При зміні самого APK (не веб-контенту — той оновлюється сам через Service Worker) користувачам треба перевстановлювати вручну.

## Безпека — після завершення роботи

Вимкнути режим розробника на телефоні:
1. Налаштування → Про телефон → Для розробників
2. Вимкнути тумблер зверху екрана

Це прибирає розділ з меню і скидає "Налагодження USB". Не впливає на вже встановлені застосунки. Увімкнути знову можна тим самим способом (7 тапів на "Номер збірки"), якщо знадобиться оновити APK у майбутньому.

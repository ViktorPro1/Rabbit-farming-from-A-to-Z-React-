# Технічні рішення

Це журнал поточного технічного стану. Він не замінює код: за розбіжностей пріоритет мають актуальні конфігураційні файли.

| Рішення                | Реалізація в проєкті                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| Клієнтський застосунок | React 19 і TypeScript, зібрані Vite 7.                                                                 |
| Навігація              | `react-router-dom`; маршрути згруповані у `src/routes/groups/` і зведені в `src/routes/AppRoutes.tsx`. |
| Дані й авторизація     | `@supabase/supabase-js`, клієнт створюється в `src/lib/supabase.ts`.                                   |
| PWA                    | `vite-plugin-pwa` генерує manifest і service worker; реєстрація налаштована на автоматичне оновлення.  |
| Індексація             | Скрипт `scripts/generate-sitemap.mjs` запускається перед TypeScript-перевіркою та збіркою.             |
| Пререндеринг           | `vite-prerender-plugin` використовує список маршрутів із `src/prerender-routes.ts`.                    |
| Деплой                 | Vercel; `vercel.json` задає заголовки безпеки та SPA-rewrite.                                          |
| Unit-тести             | Vitest з React Testing Library у JSDOM.                                                                |
| E2E-тести              | Playwright у Chromium проти production-preview.                                                        |

## Як фіксувати нове рішення

Додайте рядок до цієї таблиці, коли зміна суттєво впливає на архітектуру, безпеку, збірку, деплой або спосіб тестування. Вкажіть конкретний файл, де реалізовано рішення, і оновіть пов’язану документацію.

# Внесення змін

## Перед початком

1. Ознайомтеся з `AGENTS.md` у корені репозиторію: він задає обов’язкові правила роботи з кодом і контентом.
2. Перевірте відповідний документ у `docs` і наявні компоненти або сторінки, щоб не дублювати функціональність.
3. Для нової сторінки додайте її до `src/pages`, зареєструйте маршрут у `src/routes/groups`, а за потреби оновіть документацію маршрутів.

## Вимоги до зміни

- Не видаляйте файли, компоненти або код без погодження.
- Не вигадуйте факти для контентних сторінок і карток розділів; використовуйте підтверджені матеріали проєкту.
- Не використовуйте `@import` у CSS — це несумісно зі збіркою проєкту.
- Не додавайте секрети, персональні дані або приватні ключі до репозиторію.
- Залишайте пояснювальний коментар у коді для кожного видалення або заміни, як вимагає `AGENTS.md`.

## Перевірка перед передаванням змін

Виконайте релевантні перевірки:

```bash
npm run lint
npm test
npm run build
```

Для змін маршрутів, PWA або авторизаційних екранів також запустіть E2E-тести після збірки:

```bash
npx playwright test
```

CI виконує lint, перевірку TypeScript, Vitest, build, а для pull request — Playwright. Деталі наведено в `.github/workflows/ci.yml` і [гайді розробника](./DEVELOPER_GUIDE.md).
